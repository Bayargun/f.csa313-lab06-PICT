# Лаборатори №6 — Category-Partition ба PICT

**Оюутны нэр:** Б. Баяргүн  
**Оюутны код:** B222270085

## Хэсэг A. Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

Тестлэх функц:

POST /transfer

{
"from": "ACC001",
"to": "ACC002",
"amount": 100,
"currency": "MNT"
}

| Параметр | Сонголт     | Төлөөлөх утга | Тайлбар                     |
| -------- | ----------- | ------------- | --------------------------- |
| From     | Valid       | ACC001        | Идэвхтэй данс               |
| From     | Frozen      | ACC003        | Царцаагдсан данс            |
| From     | Missing     | ACC999        | Байхгүй данс                |
| To       | Valid       | ACC002        | Хүлээн авагчийн данс        |
| To       | Missing     | ACC998        | Байхгүй данс                |
| To       | SameAsFrom  | ACC001        | Өөрийн данс руу шилжүүлэх   |
| Amount   | Normal      | 100           | Зөв дүн                     |
| Amount   | Zero        | 0             | Тэг дүн                     |
| Amount   | Negative    | -100          | Сөрөг дүн                   |
| Amount   | OverBalance | 2000000       | Үлдэгдлээс хэтэрсэн         |
| Amount   | OverLimit   | 1500000       | Өдрийн лимитээс хэтэрсэн    |
| Currency | Same        | MNT           | Дансны валюттай ижил        |
| Currency | Different   | USD           | Ханш хөрвүүлэх шаардлагатай |

### Далд орчны нөхцөл

- ACC001: MNT данс, үлдэгдэл 1,000,000 MNT.
- ACC002: MNT данс, идэвхтэй.
- ACC003: царцаагдсан данс.
- ACC999, ACC998: системд байхгүй данс.
- Өдрийн үлдсэн лимит: 500,000 MNT.
- Валютын ханш: 1 USD = 3,500 MNT.
- Өдрийн лимитийн үлдэгдэл болон дансны үлдэгдлийг
  валют хөрвүүлсний дараа шалгана.

### Алдааны давуу эрэмбэ

ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO →
ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT →
ERROR_INSUFFICIENT → ERROR_LIMIT

Олон алдаа зэрэг илэрвэл эхлээд дансны хүчинтэй байдал,
дараа нь шилжүүлгийн дүнг шалгах нь логикийн хувьд
тохиромжтой тул энэ эрэмбийг сонгов.

### A2. Хязгаарлалтууд

| Параметр | Сонголт     | Тэмдэглэгээ | Үндэслэл                                 |
| -------- | ----------- | ----------- | ---------------------------------------- |
| From     | Valid       | -           | Хэвийн утга                              |
| From     | Frozen      | [ERROR]     | Царцаагдсан данснаас шилжүүлэх боломжгүй |
| From     | Missing     | [ERROR]     | Байхгүй данс                             |
| To       | Valid       | -           | Хэвийн утга                              |
| To       | Missing     | [ERROR]     | Байхгүй данс                             |
| To       | SameAsFrom  | [ERROR]     | Өөрийн данс руу шилжүүлэх боломжгүй      |
| Amount   | Normal      | -           | Үлдэгдэл, лимитэд багтана                |
| Amount   | Zero        | [ERROR]     | amount > 0 нөхцөлийг зөрчинө             |
| Amount   | Negative    | [ERROR]     | amount > 0 нөхцөлийг зөрчинө             |
| Amount   | OverBalance | [ERROR]     | Дансны үлдэгдэл хүрэлцэхгүй              |
| Amount   | OverLimit   | [ERROR]     | Өдрийн лимит хэтэрсэн                    |
| Currency | Same        | -           | Хөрвүүлэлт шаардлагагүй                  |
| Currency | Different   | -           | Ханш хөрвүүлэлт хийгдэнэ                 |

#### [SINGLE] нөхцөл

Amount = Negative утгыг [SINGLE] гэж тэмдэглэнэ.

Сөрөг дүн нь тэгээс бага утгын тусгай алдааны
ангилал тул бусад параметрийн бүх хослолтой
давтан шалгах шаардлагагүй.

#### [IF] нөхцөл

1. From = Missing бол Amount = Normal.
2. To = Missing бол Amount = Normal.
3. From = Frozen бол To = Valid.
4. To = SameAsFrom бол From = Valid.

Эдгээр нөхцөл нь тодорхой алдааг тусгаарлаж,
хүлээгдэх үр дүнг хоёрдмол утгагүй болгоход
зориулагдсан.

#### Бүрэн олонлог

From = 3
To = 3
Amount = 5
Currency = 2

N = 3 × 3 × 5 × 2 = 90

Хязгаарлалтын дараах тоог PICT загварт
ижил нөхцөлүүдийг хэрэгжүүлсний дараа тооцно.

## Хэсэг B. PICT Pairwise Testing

#### B1. Browser Model

| Үзүүлэлт                    | Тестийн тоо |
| --------------------------- | ----------: |
| Бүрэн олонлог               |         144 |
| Лекцийн гараар хийсэн 2-way |           9 |
| PICT 2-way                  |          10 |
| PICT 3-way                  |          20 |

PICT-ийн 2-way тестээр 10 мөр үүссэн бөгөөд
лекцийн гараар боловсруулсан 9 мөрөөс нэгээр олон байна.
Учир нь PICT greedy алгоритм ашигладаг тул бүх хослолыг
хамруулах боловч хамгийн цөөн тестийн тоог баталгаажуулдаггүй.

3-way тестээр 20 мөр үүссэн нь 2-way-ээс хоёр дахин олон
боловч бүрэн олонлог болох 144 мөрөөс 124 мөрөөр цөөн байна.

#### Бүрэн олонлог ба хязгаарлалтын дараах тоо

Бүрэн олонлог:

N = 3 × 3 × 5 × 2 = 90

[IF] хязгаарлалтуудыг хэрэглэсний дараа:

M = 36

Иймээс:

**90 → 36**

Хязгаарлалтууд нь олон алдаатай зарим хослолыг
хасаж, алдааны шалтгааныг тусгаарлахад чиглэсэн.

[SINGLE] тэмдэглэгээг энэ тооцоонд тусад нь авч үзсэн.

### B2. Transfer Model-ийн харьцуулалт

PICT ашиглан шилжүүлгийн функцийн гурван төрлийн
моделийг боловсруулж, pairwise тест үүсгэсэн.

| Үзүүлэлт                     | transfer-nc | transfer | transfer-neg |
| ---------------------------- | ----------: | -------: | -----------: |
| Нийт тест                    |          15 |       14 |           18 |
| Happy path                   |           0 |        0 |            2 |
| Алдаатай тест                |          15 |       14 |           16 |
| Нэг мөр дэх хамгийн их алдаа |           3 |        2 |            1 |
| Олон алдаатай мөр            |          10 |        4 |            0 |

#### 1. Хязгаарлалтгүй модель

transfer-nc.model нь нийт 15 тест үүсгэсэн.

Энэ моделд нэг тестийн мөрөнд хэд хэдэн алдаа
зэрэг орсон. Тухайлбал:

Frozen SameAsFrom Negative Different

Энэ мөрөнд:

- From данс царцаагдсан.
- To данс From-той ижил.
- Amount сөрөг утгатай.

Тогтоосон давуу эрэмбээр ERROR_FROZEN буцна.

Ийм олон алдаатай мөр нь error masking үүсгэж,
бусад алдааг тусад нь шалгах боломжийг хязгаарладаг.

#### 2. IF хязгаарлалттай модель

transfer.model нь нийт 14 тест үүсгэсэн.

IF хязгаарлалтуудыг хэрэглэснээр зарим
боломжгүй болон олон алдаатай хослол хасагдсан.

Гэсэн хэдий ч нэг мөрөнд хоёр алдаа
зэрэг орсон тохиолдлууд хэвээр байна.

#### 3. Negative модель

transfer-neg.model нь нийт 18 тест үүсгэсэн.

Алдаатай утгуудыг ~ тэмдэглэгээгээр тодорхойлсноор
нэг тестэд хамгийн ихдээ нэг алдаа орсон.

Мөн хоёр happy path үүссэн:

Valid Valid Normal Same
Valid Valid Normal Different

Negative модель нь алдааны шалтгааныг
тусгаарлаж шалгахад илүү тохиромжтой.

#### IF хязгаарлалт шаардлагатай юу?

Negative тэмдэглэгээ нь нэг мөрөнд олон алдаа
зэрэг орохоос сэргийлдэг боловч параметрүүдийн
бүх логик хамаарлыг илэрхийлэхгүй.

Тиймээс A2-д тодорхойлсон IF хязгаарлалтуудыг
бүрэн орлуулахгүй.

### B3. Дүгнэлт

1. Category-Partition арга нь параметрүүдийн сонголт,
   алдааны нөхцөл болон хүлээгдэх үр дүнг тодорхойлоход
   тохиромжтой байсан.
2. Гараар боловсруулсан спецификацийн хүснэгт нь
   алдааны семантикийг илүү тодорхой харуулсан.
3. PICT нь параметрүүдийн хослолыг автоматаар үүсгэж,
   pairwise хамралтыг хангадаг давуу талтай.
4. Browser моделийн 2-way тест 10 мөр,
   3-way тест 20 мөр болсон.
5. PICT-ийн greedy алгоритм хамгийн бага тестийн
   тоог заавал гаргадаггүйг ажигласан.
6. Хязгаарлалтгүй transfer моделд олон алдаа
   нэг мөрөнд зэрэг орсон.
7. IF хязгаарлалтууд зарим олон алдаатай
   хослолыг хасах боломж олгосон.
8. Negative тэмдэглэгээ ашигласнаар алдаануудыг
   тусгаарлаж шалгах боломжтой болсон.
9. Хамгийн их бодол шаардсан хэсэг нь алдааны
   давуу эрэмбэ болон хязгаарлалтыг тодорхойлох
   байсан.
