# Лаборатори №6 — Category-Partition ба PICT

**Оюутны нэр:** Б. Баяргүн  
**Оюутны код:** B222270085

## Хэсэг A. Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

Тестлэх функц:

POST /transfer

{
"from": "ACC001",
"to": "ACC002",
"amount": 100,
"currency": "MNT"
}

| Параметр | Сонголт     | Төлөөлөх утга | Тайлбар                                   |
| -------- | ----------- | ------------- | ----------------------------------------- |
| From     | Valid       | ACC001        | Идэвхтэй данс                             |
| From     | Frozen      | ACC003        | Царцаагдсан данс                          |
| From     | Missing     | ACC999        | Байхгүй данс                              |
| To       | Valid       | ACC002        | Хүлээн авагчийн данс                      |
| To       | Missing     | ACC998        | Байхгүй данс                              |
| To       | SameAsFrom  | ACC001        | Өөрийн данс руу шилжүүлэх                 |
| Amount   | Normal      | 100           | Зөв дүн                                   |
| Amount   | Zero        | 0             | Тэг дүн                                   |
| Amount   | Negative    | -100          | Сөрөг дүн                                 |
| Amount   | OverBalance | 2000000       | Үлдэгдлээс хэтэрсэн (MNT)                 |
| Amount   | OverLimit   | 600000        | Өдрийн лимитээс их, үлдэгдлээс бага (MNT) |
| Currency | Same        | MNT           | Дансны валюттай ижил                      |
| Currency | Different   | USD           | Ханш хөрвүүлэх шаардлагатай               |

> **Засвар:** өмнө нь OverLimit = 1,500,000 байсан. Энэ нь үлдэгдэл
> 1,000,000-аас их тул давуу эрэмбээр ERROR_INSUFFICIENT нь ERROR_LIMIT-ээс
> өмнө шалгагдаж, тест бодитоор ERROR_INSUFFICIENT буцаах байсан.
> OverLimit нь **лимитээс (500,000) их, үлдэгдлээс (1,000,000) бага** байх
> ёстой тул 600,000 болгов.

**USD (Currency = Different) үеийн дүн:** amount нь `currency` талбарт заасан
валютаар өгөгдөж, шалгалтын өмнө MNT руу хөрвүүлэгдэнэ (1 USD = 3,500 MNT).

| Amount      | USD дүн | MNT-ээр хөрвүүлсэн | Тайлбар                               |
| ----------- | ------: | -----------------: | ------------------------------------- |
| Normal      |     100 |            350,000 | Лимит, үлдэгдэлд багтана              |
| OverBalance |    1000 |          3,500,000 | Үлдэгдэл 1,000,000-аас хэтэрнэ        |
| OverLimit   |     200 |            700,000 | Лимит 500,000-аас их, үлдэгдлээс бага |

### Далд орчны нөхцөл

- ACC001: MNT данс, үлдэгдэл 1,000,000 MNT.
- ACC002: MNT данс, идэвхтэй.
- ACC003: царцаагдсан данс.
- ACC999, ACC998: системд байхгүй данс.
- Өдрийн үлдсэн лимит: 500,000 MNT.
- Валютын ханш: 1 USD = 3,500 MNT.
- Өдрийн лимитийн үлдэгдэл болон дансны үлдэгдлийг
  валют хөрвүүлсний дараа шалгана.

### Алдааны давуу эрэмбэ

ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO →
ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT →
ERROR_INSUFFICIENT → ERROR_LIMIT

Олон алдаа зэрэг илэрвэл эхлээд дансны хүчинтэй байдал,
дараа нь шилжүүлгийн дүнг шалгах нь логикийн хувьд
тохиромжтой тул энэ эрэмбийг сонгов.

### A2. Хязгаарлалтууд

| Параметр | Сонголт     | Тэмдэглэгээ | Үндэслэл                                 |
| -------- | ----------- | ----------- | ---------------------------------------- |
| From     | Valid       | -           | Хэвийн утга                              |
| From     | Frozen      | [ERROR]     | Царцаагдсан данснаас шилжүүлэх боломжгүй |
| From     | Missing     | [ERROR]     | Байхгүй данс                             |
| To       | Valid       | -           | Хэвийн утга                              |
| To       | Missing     | [ERROR]     | Байхгүй данс                             |
| To       | SameAsFrom  | [ERROR]     | Өөрийн данс руу шилжүүлэх боломжгүй      |
| Amount   | Normal      | -           | Үлдэгдэл, лимитэд багтана                |
| Amount   | Zero        | [ERROR]     | amount > 0 нөхцөлийг зөрчинө             |
| Amount   | Negative    | [ERROR]     | amount > 0 нөхцөлийг зөрчинө             |
| Amount   | OverBalance | [ERROR]     | Дансны үлдэгдэл хүрэлцэхгүй              |
| Amount   | OverLimit   | [ERROR]     | Өдрийн лимит хэтэрсэн                    |
| Currency | Same        | -           | Хөрвүүлэлт шаардлагагүй                  |
| Currency | Different   | -           | Ханш хөрвүүлэлт хийгдэнэ                 |

#### [SINGLE] нөхцөл

Amount = Negative утгыг [SINGLE] гэж тэмдэглэнэ.

Сөрөг дүн нь тэгээс бага утгын тусгай алдааны
ангилал тул бусад параметрийн бүх хослолтой
давтан шалгах шаардлагагүй.

#### [IF] нөхцөл

1. From = Missing бол Amount = Normal.
2. To = Missing бол Amount = Normal.
3. From = Frozen бол To = Valid.
4. To = SameAsFrom бол From = Valid.

Эдгээр нөхцөл нь тодорхой алдааг тусгаарлаж,
хүлээгдэх үр дүнг хоёрдмол утгагүй болгоход
зориулагдсан.

#### Бүрэн олонлог

From = 3
To = 3
Amount = 5
Currency = 2

N = 3 × 3 × 5 × 2 = 90

Хязгаарлалтын дараах тоог PICT загварт
ижил нөхцөлүүдийг хэрэгжүүлсний дараа тооцно.

## Хэсэг B. PICT Pairwise Testing

#### B1. Browser Model

| Үзүүлэлт                    | Тестийн тоо |
| --------------------------- | ----------: |
| Бүрэн олонлог               |         144 |
| Лекцийн гараар хийсэн 2-way |           9 |
| PICT 2-way                  |          10 |
| PICT 3-way                  |          20 |

PICT-ийн 2-way тестээр 10 мөр үүссэн бөгөөд
лекцийн гараар боловсруулсан 9 мөрөөс нэгээр олон байна.
Учир нь PICT greedy алгоритм ашигладаг тул бүх хослолыг
хамруулах боловч хамгийн цөөн тестийн тоог баталгаажуулдаггүй.

3-way тестээр 20 мөр үүссэн нь 2-way-ээс хоёр дахин олон
боловч бүрэн олонлог болох 144 мөрөөс 124 мөрөөр цөөн байна.

#### Бүрэн олонлог ба хязгаарлалтын дараах тоо

Бүрэн олонлог:

N = 3 × 3 × 5 × 2 = 90

[IF] хязгаарлалтуудыг хэрэглэсний дараа:

M = 36

Иймээс:

**90 → 36**

Хязгаарлалтууд нь олон алдаатай зарим хослолыг
хасаж, алдааны шалтгааныг тусгаарлахад чиглэсэн.

[SINGLE] тэмдэглэгээг энэ тооцоонд тусад нь авч үзсэн.

#### 90 → 36 тооцооны задаргаа

(From, To) хос бүрээр [IF] дүрмийг хэрэглэж, зөвшөөрөгдөх Amount-ийн
тоог тоолно:

| From     | To         | Хамаарах дүрэм           | Amount-ийн тоо |
| -------- | ---------- | ------------------------ | -------------: |
| Valid    | Valid      | -                        |              5 |
| Valid    | Missing    | №2 → Amount = Normal     |              1 |
| Valid    | SameAsFrom | №4 хангана               |              5 |
| Frozen   | Valid      | №3 хангана               |              5 |
| Frozen   | Missing    | №3 зөрчинө               |              0 |
| Frozen   | SameAsFrom | №3, №4 зөрчинө           |              0 |
| Missing  | Valid      | №1 → Amount = Normal     |              1 |
| Missing  | Missing    | №1, №2 → Amount = Normal |              1 |
| Missing  | SameAsFrom | №4 зөрчинө               |              0 |
| **Нийт** |            |                          |         **18** |

Currency-ийн 2 утгаар үржүүлбэл: 18 × 2 = **36**.

Хасагдсан тоог шалгах: 90 − 36 = 54.

- (Frozen, Missing), (Frozen, SameAsFrom), (Missing, SameAsFrom) гэсэн
  3 хос бүрэн хасагдсан: 3 × 5 × 2 = 30.
- (Valid, Missing), (Missing, Valid), (Missing, Missing) хосуудад Normal-аас
  бусад 4 Amount хасагдсан, тус бүр 4 × 2 = 8 мөр: 3 × 8 = 24.
- 30 + 24 = 54. Тооцоо таарна.

### B2. Transfer Model-ийн харьцуулалт

PICT ашиглан шилжүүлгийн функцийн гурван төрлийн
моделийг боловсруулж, pairwise тест үүсгэсэн.

| Үзүүлэлт                     | transfer-nc | transfer | transfer-neg |
| ---------------------------- | ----------: | -------: | -----------: |
| Нийт тест                    |          15 |       14 |           18 |
| Happy path                   |           0 |        0 |            2 |
| Алдаатай тест                |          15 |       14 |           16 |
| Яг нэг алдаатай мөр          |           3 |        5 |           16 |
| Олон алдаатай мөр            |          12 |        9 |            0 |
| Нэг мөр дэх хамгийн их алдаа |           3 |        2 |            1 |

#### 1. Хязгаарлалтгүй модель

transfer-nc.model нь нийт 15 тест үүсгэсэн.

Эдгээрээс 12 мөр нь олон алдаатай бөгөөд 5 мөрөнд гурван алдаа
зэрэг орсон. Тухайлбал:

Frozen SameAsFrom Negative Different

Энэ мөрөнд:

- From данс царцаагдсан.
- To данс From-той ижил.
- Amount сөрөг утгатай.

Тогтоосон давуу эрэмбээр ERROR_FROZEN буцна.

Ийм олон алдаатай мөр нь error masking үүсгэж,
бусад алдааг тусад нь шалгах боломжийг хязгаарладаг.

#### 2. IF хязгаарлалттай модель

transfer.model нь нийт 14 тест үүсгэсэн.

IF хязгаарлалтууд гурван алдаатай мөрийг бүрэн арилгасан (3 → 0),
хоёр алдаатай мөрийн тоог 12-оос 9 болгож цөөлсөн. Гэсэн хэдий ч
нэг мөрөнд хоёр алдаа зэрэг орсон 9 мөр хэвээр байна.

Error masking-ийн жишээ: `Frozen Valid OverBalance Different` мөрөнд
ERROR_FROZEN буцах тул ERROR_INSUFFICIENT шалгагдахгүй. Нэг мөрөнд
хоёр алдаа орвол ингэж нэг нь нөгөөгөө далдалдаг.

#### 3. Negative модель

transfer-neg.model нь нийт 18 тест үүсгэсэн.

Алдаатай утгуудыг ~ тэмдэглэгээгээр тодорхойлсноор
нэг тестэд хамгийн ихдээ нэг алдаа орсон.

Мөн хоёр happy path үүссэн:

Valid Valid Normal Same
Valid Valid Normal Different

Negative модель нь алдааны шалтгааныг
тусгаарлаж шалгахад илүү тохиромжтой.

#### IF хязгаарлалт шаардлагатай юу?

Negative тэмдэглэгээ нь нэг мөрөнд олон алдаа
зэрэг орохоос сэргийлдэг боловч параметрүүдийн
бүх логик хамаарлыг илэрхийлэхгүй.

Тиймээс A2-д тодорхойлсон IF хязгаарлалтуудыг
бүрэн орлуулахгүй.

### B3. Бодит тест кейс (transfer-neg.model-оос)

PICT-ийн transfer-neg гаралтаас happy path 2, нэг алдаатай 3 мөрийг
сонгон бодит тест кейс болгов. Тест бүр setup, body, oracle гэсэн
гурван хэсэгтэй.

**Нийтлэг setup (тест бүрийн өмнө төлөвийг шинэчилнэ):**

- ACC001: MNT, үлдэгдэл 1,000,000
- ACC002: MNT, идэвхтэй
- ACC003: царцаагдсан
- Өдрийн үлдсэн лимит: 500,000 MNT
- Ханш: 1 USD = 3,500 MNT

**Таамаглал:** `amount` нь `currency` талбарт заасан валютаар өгөгдөж,
шалгалтын өмнө MNT руу хөрвүүлэгдэнэ. Хариуны бүтэц (`status`, `code`)
нь API-ийн бодит хариугаар солигдоно.

| ID     | Төрөл      | PICT мөр (From To Amount Currency) |
| ------ | ---------- | ---------------------------------- |
| TC-N01 | Happy path | Valid Valid Normal Same            |
| TC-N02 | Happy path | Valid Valid Normal Different       |
| TC-N03 | Нэг алдаа  | ~Frozen Valid Normal Same          |
| TC-N04 | Нэг алдаа  | Valid Valid ~Negative Same         |
| TC-N05 | Нэг алдаа  | Valid Valid ~OverLimit Different   |

#### TC-N01 — Happy path (ижил валют)

- **Setup:** нийтлэг setup
- **Body:** `{"from":"ACC001","to":"ACC002","amount":100,"currency":"MNT"}`
- **Oracle:**
  - Хариу: HTTP 201, `OK`
  - ACC001 = 999,900
  - ACC002 += 100
  - Өдрийн лимитийн үлдэгдэл = 499,900

#### TC-N02 — Happy path (ханш хөрвүүлэлттэй)

- **Setup:** нийтлэг setup
- **Body:** `{"from":"ACC001","to":"ACC002","amount":100,"currency":"USD"}`
- **Oracle:**
  - Хөрвүүлэлт: 100 × 3,500 = 350,000 MNT
  - Хариу: HTTP 201, `OK`
  - ACC001 = 650,000
  - ACC002 += 350,000
  - Лимитийн үлдэгдэл = 150,000

#### TC-N03 — Нэг алдаа: царцаагдсан данс

- **Setup:** нийтлэг setup
- **Body:** `{"from":"ACC003","to":"ACC002","amount":100,"currency":"MNT"}`
- **Oracle:**
  - Хариу: HTTP 200, `ERROR_FROZEN`
  - Аль ч дансны үлдэгдэл, лимит **өөрчлөгдөхгүй**

#### TC-N04 — Нэг алдаа: сөрөг дүн

- **Setup:** нийтлэг setup
- **Body:** `{"from":"ACC001","to":"ACC002","amount":-100,"currency":"MNT"}`
- **Oracle:**
  - Хариу: HTTP 200, `ERROR_BAD_AMOUNT`
  - Үлдэгдэл, лимит өөрчлөгдөхгүй

#### TC-N05 — Нэг алдаа: өдрийн лимит (USD)

- **Setup:** нийтлэг setup
- **Body:** `{"from":"ACC001","to":"ACC002","amount":200,"currency":"USD"}`
- **Oracle:**
  - Хөрвүүлэлт: 200 × 3,500 = 700,000 MNT
  - 700,000 ≤ үлдэгдэл 1,000,000 тул ERROR_INSUFFICIENT биш
  - 700,000 > лимит 500,000 тул `ERROR_LIMIT`
  - Хариу: HTTP 200, `ERROR_LIMIT`
  - Үлдэгдэл, лимит өөрчлөгдөхгүй

### B4. Дүгнэлт

1. Category-Partition арга нь параметрүүдийн сонголт,
   алдааны нөхцөл болон хүлээгдэх үр дүнг тодорхойлоход
   тохиромжтой байсан.
2. Гараар боловсруулсан спецификацийн хүснэгт нь
   алдааны семантикийг илүү тодорхой харуулсан.
3. PICT нь параметрүүдийн хослолыг автоматаар үүсгэж,
   pairwise хамралтыг хангадаг давуу талтай.
4. Browser моделийн 2-way тест 10 мөр,
   3-way тест 20 мөр болсон.
5. PICT-ийн greedy алгоритм хамгийн бага тестийн
   тоог заавал гаргадаггүйг ажигласан.
6. Хязгаарлалтгүй transfer-nc моделд 15 мөрийн 12 нь олон алдаатай
   байсан бөгөөд 5 мөрөнд гурван алдаа нэг мөрөнд зэрэг орсон.
7. IF хязгаарлалтууд гурван алдаатай мөрийг бүрэн арилгаж,
   олон алдаатай мөрийг 12-оос 9 болгон цөөлсөн ч бүрэн арилгаагүй.
8. Negative тэмдэглэгээ ашигласнаар алдаануудыг
   тусгаарлаж шалгах боломжтой болсон.
9. Хамгийн их бодол шаардсан хэсэг нь алдааны
   давуу эрэмбэ болон хязгаарлалтыг тодорхойлох
   байсан.
10. Бодит тест кейс бичихдээ setup, body, oracle-ийг ялгаж, oracle-д
    хариуны код болон төлөвийн өөрчлөлтийг (үлдэгдэл, өдрийн лимит)
    шалгадаг болсон.
11. Тест кейс бичих явцад A1-ийн OverLimit утга (1,500,000) нь үлдэгдлээс
    их тул давуу эрэмбээр ERROR_INSUFFICIENT буцаах байсныг илрүүлж,
    600,000 MNT / 200 USD болгон засав.
